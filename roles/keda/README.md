Kubernetes cluster using its helm chart.

## Requirements

- Minimum Ansible version: `2.17`

## Default Variables

### keda_additional_helm_values

Additional helm values to be passed to the chart.
Use this to configure any chart option not exposed as a dedicated variable.
ref: https://github.com/kedacore/charts/blob/main/keda/values.yaml

**_Type:_** dict<br />

#### Default value

```YAML
keda_additional_helm_values: {}
```

### keda_affinity

Affinity for the KEDA pods

**_Type:_** dict<br />

#### Default value

```YAML
keda_affinity: {}
```

### keda_cert_manager_enabled

Use cert-manager to issue and rotate the KEDA TLS certificates instead of
the certificates self-generated by the operator

**_Type:_** boolean<br />

#### Default value

```YAML
keda_cert_manager_enabled: false
```

### keda_cert_manager_issuer

Issuer used by cert-manager. When `generate` is false, `name`, `kind` and
`group` are required and must reference an existing issuer

**_Type:_** dict<br />

#### Default value

```YAML
keda_cert_manager_issuer: {}
```

#### Example usage

```YAML
keda_cert_manager_issuer:
  generate: false
  name: "letsencrypt"
  kind: "ClusterIssuer"
  group: "cert-manager.io"
```

### keda_cluster_domain

Kubernetes cluster domain

**_Type:_** string<br />

#### Default value

```YAML
keda_cluster_domain: cluster.local
```

### keda_cluster_name

Kubernetes cluster name, used in features such as emitting CloudEvents

**_Type:_** string<br />

#### Default value

```YAML
keda_cluster_name: kubernetes-default
```

### keda_crds_additional_annotations

Custom annotations added to the KEDA CRDs only

**_Type:_** dict<br />

#### Default value

```YAML

```

### keda_crds_install

Let the chart render the KEDA CRDs. Set to false when the CRDs are
managed outside of this role (e.g. applied from the released
`keda-<version>-crds.yaml` manifest)

**_Type:_** boolean<br />

#### Default value

```YAML
keda_crds_install: true
```

### keda_crds_upgrade_enabled

Apply KEDA CRDs (server-side, force conflicts) before helm upgrade.
The KEDA CRDs exceed the 262144 bytes limit of the client-side
`last-applied-configuration` annotation, so we render the target chart with
`helm_template --include-crds` and apply only the CustomResourceDefinition
resources. Skipped on first install since `helm install` already applies the
CRDs rendered by the chart.

**_Type:_** boolean<br />

#### Default value

```YAML
keda_crds_upgrade_enabled: true
```

### keda_deployment_name

Deployment name for KEDA helm chart

**_Type:_** string<br />

```YAML
keda_deployment_name: keda
```

### keda_enabled

**_Type:_** boolean<br />

#### Default value

```YAML
keda_enabled: true
```

### keda_extra_objects

Extra Kubernetes manifests deployed along with the chart, useful to declare
cluster wide KEDA resources such as ClusterTriggerAuthentication

**_Type:_** list<br />

#### Default value

```YAML
keda_extra_objects: []
```

#### Example usage

```YAML
keda_extra_objects:
  - apiVersion: "keda.sh/v1alpha1"
    kind: "ClusterTriggerAuthentication"
    metadata:
      name: "aws-credentials"
    spec:
      podIdentity:
        provider: "aws-eks"
```
